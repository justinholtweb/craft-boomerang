# Plugin Store promo images

Marketing images for the Boomerang listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-boomerang](https://justinholt.com/plugins/craft-boomerang).

They live in the plugin repo, not beside a site, because Boomerang is one of the plugins that lives
as a page on justinholt.com rather than on its own domain.

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `boomerang-promo-N.png`, 1920×1080 (rendered at 2× in headless Chrome,
then downsampled so the type stays crisp).

## Notes

`assets/icon.svg` **is** a straight copy of `../src/icon.svg`. Boomerang's icon is hand-authored:
the tile is a real `<rect>` and the mark is two stroked paths, so there is no full-canvas white
frame path to strip and no transparent padding to crop out. Copy it over whole when the icon
changes.

`assets/watermark.svg` is `../src/icon-mask.svg` with `stroke="#000"` switched to `#ffffff`.
**Three files, one geometry** — change the icon and change all three.

**The watermark opacity had to come down, not up.** The reasoning that got it wrong first: Boomerang's
mark is *strokes* rather than a filled figure, so it looked like it would need more opacity than the
family's filled-mark 0.020, not less. It needs far less. At the 960px watermark size the 15px chevron
scales to a ~144px bar, which lays down more contiguous ink than Bee's airy four-winged silhouette
does — 0.032 put a plainly legible chevron behind every headline, and 0.014 was still catching the
eye on the centred slides. **0.008** is the point where it is present without being seen. The crop
also has to stay gentle (`left: -12%`, against Bee's `-17%` and Bouncer's `-20%`): crop a stroked
chevron hard and what is left reads as a stray diagonal rule rather than as the icon.

Two layout rules inherited from the rest of the family, both of which bit again:

- **One line per bullet, about 55 characters at 25px.** The copy column is 780px inside a 130px
  gutter and the panel starts at `left: 900px`, so a bullet that wraps runs at the panel and lands
  on top of it — nothing clips, the text simply overlaps. Nine of the first-draft bullets were over,
  the worst at 66 characters.
- **`.points li` is a flex container.** An inline `<span class="mono">` left loose in the text
  becomes a *sibling flex item* and picks up the 16px gap on both sides. Every point keeps its text
  in one `<span class="t">`.

**Slide 2's swap line is 41 characters, not Bee's 28.** `.swap .after` is 48px here rather than the
family's 68px for that reason; at 68px `requested → approved → received → resolved` runs the full
width of the canvas and breaks the centred composition.

**`.place .chip` drops the family's `text-transform: uppercase`.** On slide 6 the chips carry the
four resolutions as the plugin names them — `refund`, `credit`, `exchange`, `restock` — and
upper-casing them makes them look like constants rather than settings.

`fonts.css` is generated by `build.sh`, which base64-inlines the two woff2 files in `assets/` —
Chrome's `file://` origin rules block them otherwise. It is gitignored; don't edit it.

## Where the screenshots come from

`shots/` is copied from `plugin-shots/out/boomerang/`. They are real captures of a real install, not
mockups: `~/Sites/plugin-testing` with thirteen RMAs spread across every state, real refunds through
the Dummy gateway, real inventory adjustments and a real wallet spend. See `../tests/shots/README.md`
for how that install is driven.

Both screenshot slides need `.cpc-clip`: the returns index and the analytics board are both long, and
at the 950px the panel gives them they come out well past the 620px cap. The fade makes the cut read
as "there is more" rather than as a broken edge.

**Slide 9 is the analytics board rather than the credit detail**, which was the first choice. The
credit detail is the better *argument* — it shows a lot drawn to zero ahead of three later ones, which
is FIFO-by-expiry proving itself — but its top 580px are the balance and the issue form, and the lots
table only starts below the clip. Capturing it pre-scrolled does not help either: Craft's element
header is sticky, so a scrolled capture lands the customer's name and the Save button across the
middle of the page. The credit index (`shots/boomerang-credit.png`) is kept here because the
marketing page's screenshot band uses it.
